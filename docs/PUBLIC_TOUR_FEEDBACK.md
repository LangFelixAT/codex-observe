# Public Tour Feedback

Use this runbook when collecting feedback from someone trying the synthetic public tour or reviewer evidence bundle. The goal is to learn whether Codex Observe helps a new user understand cost and context growth without asking them to share private Codex logs.

## Safe Feedback Sources

- `codex-observe tour` output.
- Synthetic demo dashboard from `codex-observe demo --serve --host 127.0.0.1 --port 8501`.
- Aggregate-only command output from `doctor`, `sessions`, `report`, and `compare` against `.artifacts/demo/codex_observe_demo.sqlite`.
- Visual QA manifest and screenshots generated from synthetic data.
- Reviewer evidence bundle generated by `codex-observe evidence-bundle --out .artifacts/public-evidence`, including `README.md`, `LIMITATIONS.md`, `evidence-bundle.json`, the review checklist, report Markdown/JSON, comparison Markdown/JSON, audit JSON, and reviewed visual artifacts.

## Do Not Collect

- Private prompts, raw `.jsonl` session logs, message text, tool commands, tool arguments, tool output, or event payload JSON.
- Local filesystem paths, usernames, repository secrets, credentials, API keys, or private database files.
- Screenshots, exported tables, issue bodies, or evidence bundles that have not been reviewed for sensitive paths or aggregate clues.
- Any real-log fixture candidate that has not followed `docs/REAL_LOG_FEEDBACK.md` and the redaction manifest/privacy review loop.

## Feedback Questions

- Could the user install and start the synthetic tour without extra explanation?
- Did the Overview, diagnostics, ranked opportunity stack, next-run playbook, and dashboard quick reads explain what made the run expensive?
- Did report and comparison artifacts give enough aggregate evidence to discuss a run without raw content?
- Did `README.md`, `LIMITATIONS.md`, and `evidence-bundle.json` make the reviewer bundle self-explanatory?
- What was the first confusing moment, missing command, misleading label, or visual polish issue?
- Which follow-up should become a fresh demoable GitHub issue, and which feedback is only a human-input reminder?

## Closeout

`codex-observe tour` ends by pointing reviewers to this runbook and `.github/ISSUE_TEMPLATE/public_tour_feedback.yml`. File feedback with `.github/ISSUE_TEMPLATE/public_tour_feedback.yml`. If feedback becomes implementation work, convert it into an implementation, parser, or visual-polish issue with acceptance criteria, tests, visual QA expectations, and privacy review notes. External attachment or publication of generated artifacts still requires explicit human approval.
